# UI/UX pass — 2026-10-28

Status: **implemented** · Scope: interaction, accessibility and typographic
hierarchy. The palette (deep navy `#0e1217`, yellow `#f1c81b`, brand orange
`#fb9b18`), the type families (Fira Code / Roboto Condensed / system sans) and
the 54rem content column are unchanged — this pass only fixes what measured
wrong, so the identity planned in [the redesign pass](redesign.md) survives
intact.

This pass was driven by the `ui-ux-pro-max` skill (design-system search for a
dark portfolio, then targeted `ux`, `icons` and stack searches) and by
measurements taken from the built site at 320/375/768/1024/1440 px, not by
taste.

## Findings and fixes

| # | Severity | Finding                                                                                                                                                                                                                                                          | Fix                                                                                                                                                                                                                            |
| - | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1 | High     | Header used a fixed `10rem` horizontal gutter at **every** width. At 320 px the header's content box was 0 px wide, so the brand + menu pair overflowed it and sat 41 px right of centre; between 768–1023 px the header items overflowed their own padding box. | `--header-padding-x` is now mobile-first (20 px) and grows to 40 px at ≥48rem and back to the legacy 160 px only at ≥80rem, where the 482 px nav actually fits. Brand + menu are exactly centred (offset 0 px at 320 and 375). |
| 2 | High     | Page titles were flat: `.page-title` rendered at 2rem (32 px) — the same size as `.section-title` — against 25.6 px body copy, with `margin: 0`, so the title touched the first paragraph.                                                                       | `.page-title` is `clamp(2.25rem, 2.5vw + 1rem, 3rem)` (36–48 px) with `1.5rem` bottom margin. At 1440 px the hierarchy read 48 / 32 / 25.6 px, later 48 / 32 / 20 px after the follow-up.                                      |
| 3 | High     | The fullscreen mobile menu had no focus management: focus stayed on the hamburger _behind_ the overlay, and Tab escaped into the page behind it.                                                                                                                 | Focus moves to the close button on open and returns to the hamburger on close; Tab is trapped inside the overlay; `main` and `footer` are `inert` while it is open; resizing to the desktop layout closes it.                  |
| 4 | Medium   | Focus rings were applied through `*:focus`, so mouse clicks on cards and buttons flashed an outline, and `.button:focus` filled the button like a hover state.                                                                                                   | Rings are keyboard-only (`*:focus-visible`) and the filled button state is `:focus-visible` too.                                                                                                                               |
| 5 | Medium   | Overlay navigation rows were ~29 px tall and the CV pill 33.6 px — below the 44 px touch target.                                                                                                                                                                 | Every overlay row is a full-width 46 px tap target (the CV pill was 44 px too until it was removed, see follow-up); the desktop nav reverts to inline text.                                                                    |
| 6 | Medium   | Secondary text had drifted into five sizes: tags 12.8 px, metadata 13.6 px, hero highlights 14.4 px, card copy 15.2 px.                                                                                                                                          | Two tokens: `--text-meta: 0.9rem` (14.4 px, tags/dates/handles) and `--text-compact: 1rem` (16 px, card copy, hero highlights).                                                                                                |

## Interaction details

- The overlay now stops animating `visibility` while it is **open**. Without
  that, the element is still `visibility: hidden` on the frame it opens and
  `focus()` on the close button is a no-op. The close transition still delays
  hiding until the slide-out finishes.
- The hamburger exposes only `aria-expanded`/`aria-controls` from the page
  template; the redundant `aria-pressed` was dropped from the island.
- Escape is ignored when the menu is already closed, and the `matchMedia`
  breakpoint listener prevents an invisible overlay from trapping focus after a
  rotate/resize to desktop.

## Follow-up from the owner review (same day)

Two product decisions came back after the first pass and changed what the site
publishes:

1. **The CV is no longer hosted.** `static/cv.pdf` was deleted and every entry
   point removed: the `cvPath` field in `data/site.ts`, the header `CV` pill
   (and its `.nav-cv` styles), the footer link, the home hero's secondary button
   and the `/contact` "CV" section (whose `basePath` prop and meta description
   referenced it). The footer now carries only GitHub and LinkedIn, and
   `/Portfolio/cv.pdf` returns 404. **The PDF is still in git history**, so the
   repository history should be rewritten (or the file confirmed as
   non-sensitive) before the repo is made public.
2. **Inner-page copy was too large.** The home page was fine because it sizes
   its hero, cards and metadata explicitly; About/Contact/Projects inherited
   `body`, which was 24 px at ≥48rem and 25.6 px at ≥80rem on an 832 px column.

### Type scale after the review

| Element                    |  Phone (375 px) | Tablet / laptop (≥48rem) | Desktop (≥80rem) |
| -------------------------- | --------------: | -----------------------: | ---------------: |
| Page title (`.page-title`) |           36 px |                 36–42 px |            48 px |
| Section title              |           24 px |                    32 px |            32 px |
| Job / education title      |           20 px |                    20 px |            24 px |
| Body copy (inner pages)    |           16 px |                    18 px |            20 px |
| Home hero intro            |           24 px |                    24 px |            24 px |
| Card copy / metadata       | 16 px / 14.4 px |          16 px / 14.4 px |  16 px / 14.4 px |

- `body` is now `1.125rem` at ≥48rem and `1.25rem` at ≥80rem (was `1.5rem` /
  `1.6rem`). The home page is untouched because its display sizes are explicit.
- Prose is capped at `--measure: 64ch` (page ledes, About paragraphs, project
  blocks and lists, experience bullets) so lines stay near the home page's
  measure instead of running ~90 characters at 20 px.
- Dependent sizes were retuned so the hierarchy does not invert: job titles
  `clamp(1.25rem, 0.9rem + 0.8vw, 1.5rem)`, `.section-lede` and `.fiche-summary`
  `1.25rem`.
